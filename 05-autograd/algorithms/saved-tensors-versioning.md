# SavedVariable：保存值、版本计数与原地修改 — 算法与不变量

## 如果前向的 x 被覆盖
令 x=2，L=x*x，前向结果 4。局部导数需要前向时刻的 x，因此正确梯度为 4。如果在 backward 前把 x 改成 3，直接读取当前 x 会得到错误的 6。自动微分必须保护保存值的语义，而不是盲目使用最新数据。

## 版本计数检测冲突
SavedVariable 在构造时记录版本。对于普通无 hooks 的 unpack，保存版本必须等于当前版本。若不一致就报错，防止使用被原地修改的保存值。下图中的 0、1 是教学示意；实际起始版本取决于张量历史。[SV-1]

## detach 与 clone 的区别
detach() 断开反向关联，但不保证独立存储；修改 detached 别名仍会影响原张量，并共享版本计数。detach().clone() 则创建独立副本。在示例中，修改别名后 backward 抛错，而修改克隆副本后仍得到梯度 4。不是所有原地操作都会报错：是否保存、是否需要旧值、别名及 grad 模式共同决定行为。不要把 no_grad 当作版本检查的绕过方式，也不要用 .data 隐藏修改。对真正需要修改的训练参数，在一次 backward 完成后通过 optimizer 按常规步骤更新。
