Autograd Engine：依赖计数与梯度汇聚

同一个中间结果被两个分支共享时，谁来决定 backward 的执行顺序？从依赖计数到 GraphTask、InputBuffer 与 ReadyQueue。

源码范围：PyTorch 2.10.0 · 449b17684101 · PyTorch 2.10 eager CPU backward 的简化共享节点调度；排除 compiled autograd、重入、GPU stream 详细调度

为什么不能收到一份梯度就执行？

设 a=2x，b=3a，c=4a，L=b+c。a 同时影响两个输出分支。若 a 的反向函数只收到 b 的贡献 3 就执行，x 会得到 6，而 c 的贡献 4 尚未处理。必须先把属于 a 同一反向输入槽位的两份贡献聚合起来，再让 a 的反向函数向 x 传播 14。

用计数器表达“等齐”

把反向方向的依赖边数记为 d(a)=2。收到 3 后，d=1，缓冲区是 3；收到 4 后，d=0，缓冲区是 7，此时可以调度 a。若先收到 4 也一样得到 7。真实引擎的依赖计数针对有效边，不等同于简单的 Tensor 使用次数；多输入 Node 有多个槽位。[ENG-2]

三个关键对象

GraphTask
一次 backward 的任务状态，包括依赖、未就绪缓冲区以及是否保留图等。
InputBuffer
以输入槽位为单位接收和累积梯度，CPU 分支可直接移动首份梯度，后续贡献执行累积。
ReadyQueue / NodeTask
依赖满足后，将 Node 与输入缓冲区交给执行队列。它不是 Python 前向操作的简单反序列表。

调用链：Python backward → Engine::execute → 创建 GraphTask → compute_dependencies → execute_with_graph_task → evaluate_function → InputBuffer / ReadyQueue。单根 eager 路径可以跳过虚拟 GraphRoot。[ENG-1]

两个不同层次的累积

分支贡献在同一次反向中的 InputBuffer 聚合，与叶子 .grad 跨多次 backward 的累积不是同一个动作。前者协调 Node 就绪；后者由 AccumulateGrad 等处理。因此训练循环通常显式清零参数梯度。实验先得到 a.grad=7（调用 retain_grad），x.grad=14；在新图执行 (2*x).backward() 后，x.grad=16。

本文只展示可验证的 CPU 简化图，不宣称多线程实际顺序固定；GPU stream 同步、设备队列、重入与 compiled autograd 是后续主题。浮点加法一般不满足严格结合律，toy 的整数结果不能证明任意顺序数值完全相等。[ENG-3]

可运行实验

环境：PyTorch 2.10.0+cpu、Python 3.13.5；使用确定性 float64 输入，未使用 GPU。toy 是教学模型，native 是 PyTorch 对照。

import torch

def toy(order):
    remaining, total = 2, 0
    trace = []
    for contribution in order:
        total += contribution
        remaining -= 1
        trace.append((remaining, total))
    assert remaining == 0
    return 2*total, trace

for order in ([3, 4], [4, 3]):
    result, trace = toy(order)
    assert result == 14
    print('toy', order, trace, result)
x = torch.tensor(2., dtype=torch.float64, requires_grad=True)
a = 2*x
a.retain_grad()
loss = 3*a + 4*a
loss.backward()
assert a.grad.item() == 7 and x.grad.item() == 14
print('native', a.grad.item(), x.grad.item())
(2*x).backward()
assert x.grad.item() == 16
print('second backward on a fresh graph:', x.grad.item())

实际输出

toy [3, 4] [(1, 3), (0, 7)] 14
toy [4, 3] [(1, 4), (0, 7)] 14
native 7.0 14.0
second backward on a fresh graph: 16.0
