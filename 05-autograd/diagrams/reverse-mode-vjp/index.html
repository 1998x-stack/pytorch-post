PYTORCH INTERNALS · AUTOGRAD / 01

反向自动微分：从链式法则到 VJP

为什么一次 backward 能计算成千上万个参数的梯度？从一条分叉的标量计算路径开始，推导向量–雅可比积，再连接 PyTorch 的反向图。

源码范围：PyTorch 2.10.0 · 449b17684101 · 实数、CPU eager、一阶反向微分；标量 loss 与显式种子的向量输出

梯度不是重新运行 N 次

设一个标量损失依赖 n 个参数。数值差分逐个扰动参数；符号微分构造导数表达式；自动微分则在实际执行的基本操作上应用局部导数。反向模式从输出开始传播余切，不需要显式构造完整雅可比矩阵。对一个标量输出，通常只需一轮反向传播取得整个梯度。[AD-2]

同一个变量被使用两次

令 a=x²，b=3x，L=a+b。x=2 时，a=4，b=6，L=10。反向以 L 的余切 1 为起点：加法向 a、b 各传 1；平方路径给 x 贡献 4，乘法路径贡献 3。x 的总梯度是 7，不是 4 或 3。

从标量推广到向量

若 y=f(x)，x∈Rⁿ、y∈Rᵐ，雅可比 J 的形状为 m×n，种子 v 的形状为 m，返回的梯度形状为 n。本文采用列向量约定。

g=JTv,gi=∑j=1mvj∂yj∂xi

例如 f(x₁,x₂)=(x₁x₂,x₁+x₂)，x=(2,3)，v=(4,5)，两个输入分别收到 4×3+5=17、4×2+5=13。非标量输出需要传入形状匹配的 grad_outputs（这里是实数向量）；默认标量种子为 1。

论文与源码的连接

2017 年论文 §1、§3 描述即时执行和反向函数图。不能将历史 Variable 包装器直接视作今天的 Tensor 结构。2.10 源码的 Python binding 组装根边与梯度输入；CPU InputBuffer 对同一输入槽位的贡献进行累积。[AD-1] [AD-2]

反向模式通常适合输出维数远小于输入维数的情况，但保存中间状态有内存成本；这里不宣称反向模式总是快于前向模式，也不把数学图等同于具体 C++ Node 图。

可运行实验

环境：PyTorch 2.10.0+cpu、Python 3.13.5；使用确定性 float64 输入，未使用 GPU。toy 是教学模型，native 是 PyTorch 对照。

import torch

def toy(x):
    a = x*x
    return a + 3*x, 2*x + 3

for value in (-2., 0., 2.):
    x = torch.tensor(value, dtype=torch.float64, requires_grad=True)
    y = x*x + 3*x
    expected, grad = toy(value)
    assert y.item() == expected
    assert torch.autograd.grad(y, x)[0].item() == grad
    print(f'x={value:g} y={expected:g} gradient={grad:g}')
x = torch.tensor([2., 3.], dtype=torch.float64, requires_grad=True)
y = torch.stack((x[0]*x[1], x[0]+x[1]))
v = torch.tensor([4., 5.], dtype=torch.float64)
g = torch.autograd.grad(y, x, v)[0]
assert torch.equal(g, torch.tensor([17., 13.], dtype=torch.float64))
print('VJP:', g.tolist())

实际输出

x=0 y=0 gradient=3
x=2 y=10 gradient=7
