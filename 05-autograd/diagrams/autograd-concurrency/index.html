Autograd 并发：ReadyQueue、重入与 CUDA Stream

反向传播的并发不只是多线程。分开理解 GraphTask 的调度、嵌套 backward 的死锁风险，以及设备流上的数据依赖。

源码范围：PyTorch 2.10.0 · 449b17684101 · PyTorch 2.10 eager CPU 独立图及嵌套反向实测；CUDA canonical stream 合约仅固定源码研究，无 GPU 实验。

区分三个不同的并发问题

两个 Python 线程同时调用 grad，是两个独立 GraphTask 的并发；一个 GraphTask 的 ready node 调度，是图内执行问题；CUDA stream 是设备异步执行与依赖问题。三者不能用同一条时间线解释。特别是 torch.set_num_threads 控制算子内部线程，不等于 Autograd worker 数。

ReadyQueue 与重入

当一个 backward node 内部再次调用 grad，外层任务需要等待内层任务。如果负责队列的唯一 worker 阻塞，内层任务可能无法推进。Engine 的重入说明描述了 worker pool 协作处理这种情况；具体路径与设备、重入深度有关，不能把每次嵌套都说成创建新线程。CPU 队列和设备队列通过 ready_queue 分派。[CONC-1]

独立输入分别求导避免共享 .grad 写入；共享叶子的梯度累积顺序和跨线程用户 hooks 的安全性仍须单独考虑。独立线程示例的 barrier 只保证两方到达求导入口，不能证明 kernel 或 C++ worker 实际重叠。

CUDA 流与 producer-consumer 合约

设备上的反向算子通常遵循对应前向流；梯度从一个生产者交给另一个消费者时，InputBuffer 负责累积及相关同步的一部分，Engine 在消费者执行前处理另一部分。canonical stream 是节点约定，不等于全设备同步。首个贡献可直接移入缓冲；后续贡献需等待相关生产流、处理 record_stream 与累积，再更新 ready event。

若在自定义流中执行 backward，再在其他流消费梯度，用户仍需建立正确的流依赖。当前仅阅读了固定源码；没有 CUDA 硬件，因此不声称实测 stream overlap。[CONC-2]

实验与边界

两个 CPU 线程分别求 x² 的梯度，x=2 和 3；结果为 4、6。自定义 Function 内部用 enable_grad 构建独立内层图，nested grad 得到 6。detach 使这个例子只用于一阶行为验证，不保证二阶导数。[CONC-3]

可运行实验

Python 3.13.5、PyTorch 2.10.0+cpu、OMP_NUM_THREADS=1。以下脚本已实际执行，退出码 0。

import threading
from concurrent.futures import ThreadPoolExecutor
import torch

torch.set_num_threads(1)
barrier = threading.Barrier(2)
def task(value):
    x = torch.tensor(value, dtype=torch.float64, requires_grad=True)
    y = x.square()
    barrier.wait(timeout=10)
    return torch.autograd.grad(y, x)[0].item()
with ThreadPoolExecutor(max_workers=2) as pool:
    result = list(pool.map(task, [2., 3.]))
assert result == [4., 6.]
print('independent CPU graph gradients:', result)
class Reenter(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)
        return x.square()
    @staticmethod
    def backward(ctx, g):
        (x,) = ctx.saved_tensors
        with torch.enable_grad():
            z = x.detach().requires_grad_()
            inner = torch.autograd.grad(z.square(), z)[0]
        return g * inner
x = torch.tensor(3., dtype=torch.float64, requires_grad=True)
Reenter.apply(x).backward()
assert x.grad.item() == 6.
print('nested backward gradient:', x.grad.item())
print('CUDA available:', torch.cuda.is_available())

实际输出

independent CPU graph gradients: [4.0, 6.0]
nested backward gradient: 6.0
CUDA available: False
