# Bootstrap 反思评审

## 设计结论

- 保留用户指定的 25 个一级模块和 8 个子目录；编号是稳定 ID，不意味着严格依赖拓扑。跨组件概念由正文链接解决，不复制研究。每目录 README 明确职责与待完成状态。
- 论文链接、源码路径仅作候选入口，不把相关论文当成直接实现来源。将 PyTorch 版本、源码 commit、实验硬件和外部依赖版本提升为强制证据。
- 不把 25 个骨架伪装成 25 篇已完成文章；不提供无证据的性能数据。第一批建议先做 Tensor/Dispatcher/Autograd，再做 FX/Dynamo/Inductor 与 DDP/FSDP。
- Vendor 实际 Skill 子树、示例及依赖，保留原始文件与上游哈希；不复制上游 CI、历史 QA、网站入口；避免把上游测试结果视作本项目结果。
- 风险：上游生成器同名覆盖；浏览器脚本相对路径/链接及键盘检查需补充；测试路径依赖上游布局；缺少明确许可证。集成指南已明确这些限制。未来独立 PR 解决脚本回归测试、CI 与发布流程。

## 验收范围

结构与 vendor 内容可通过 scripts/validate_structure.py 校验。论文逐条核验、源码运行、GPU 性能实验、浏览器文章 QA 与 Pages 部署不属于本次骨架构建，不得标为通过。
